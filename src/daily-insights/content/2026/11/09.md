### Goldman Sachs Is Pulling Claude Code From Its Bankers and Traders
**Source:** State of AI · **Category:** AI · **Link:** [Original](https://www.thestateofai.com/news/goldman-sachs-claude-code-traders-bankers)
- October guidance reportedly limits Anthropic’s Claude Code and Microsoft’s GitHub to Goldman Sachs engineers, while “strats” retain access.
- Bankers and traders had used coding agents to monitor client flows, model markets and positions, and prepare written and visual materials.
- Goldman cites productivity and risk review; the article points to code review, information barriers, cost, and missing replacement workflows as key considerations.

## 📝 Detailed Notes

### 1. Goldman Sachs Is Pulling Claude Code From Its Bankers and Traders

1. October guidance narrows who can use coding agents.
   - Bloomberg reported that Goldman Sachs limited Anthropic’s Claude Code and Microsoft’s GitHub to engineers.
   - The policy followed a review of productivity and risk concerns.
   - Staff in “strats,” spanning trading, quantitative research, and software engineering, reportedly retain access.
   - Some traders were frustrated because they had used these tools in daily work.
2. Earlier practice encouraged employees to prototype tools.
   - In July, CIO Marco Argenti praised nontechnical employees’ “vibe coding” and said engineers could improve the resulting tools.
   - Traders and bankers used agents to track client trading flows and model market moves and positions.
   - They also prepared written and graphic materials with the tools.
   - The approach let employees close to a problem create a first version without waiting for engineering capacity.
   - Goldman has about 12,000 engineers among roughly 47,000 employees, according to Argenti’s remarks cited in the article.
3. The restriction differs from the earlier Hong Kong decision.
   - Goldman removed Claude from its Hong Kong bankers’ internal AI platform in April, citing contract interpretation and availability.
   - ChatGPT and Gemini reportedly remained available to those bankers.
   - The newer restriction is based on employee role and applies to third-party agents that can write and run code.
   - Goldman’s internal assistant, which uses models from several companies, remains available firmwide.
4. Code execution creates control and accountability risks.
   - Claude Code can read files, write programs, and run them with the user’s access.
   - Engineer-authored code usually goes through review, testing, and deployment controls; trader-built scripts may enter daily use without them.
   - Banks must maintain information barriers, such as separating deal teams from traders who could benefit from deal information.
   - An agent-built tool may not include those controls, and engineers may not inspect it unless it is submitted for review.
   - Users who cannot understand generated code may miss edge cases in position models, creating potential trading losses.
5. The article calls for clear ownership and a path for useful tools.
   - Goldman and Morgan Stanley are lead underwriters for Anthropic’s IPO, expected to list on Nasdaq under ticker ANT before the end of November, according to the article.
   - The authors consider restricting unreviewed code sensible in a regulated business, but criticize withdrawing access without a reported replacement.
   - They recommend assigning a named engineer responsibility for agent-built tools before those tools touch production data.
   - Existing information barriers, data permissions, and software approval rules should apply regardless of whether code came from a prompt.
   - When organizations remove a tool, they should record the tasks it supported so those needs can be addressed.
   - The article also notes possible token costs and contrasts Goldman’s approach with Barclays’ plan to expand Claude Code use among developers.

### 골드만삭스, 은행원과 트레이더의 클로드 코드 사용 제한
**출처:** State of AI · **카테고리:** 인공지능 · **링크:** [원문](https://www.thestateofai.com/news/goldman-sachs-claude-code-traders-bankers)
- 블룸버그 보도에 따르면 골드만삭스는 10월 지침으로 앤스로픽(Anthropic)의 클로드 코드(Claude Code)와 마이크로소프트(Microsoft)의 깃허브(GitHub)를 엔지니어만 사용하도록 제한했으며, 트레이딩 전략 담당자(strats)는 계속 이용할 수 있다.
- 은행원과 트레이더는 코딩 에이전트로 고객 거래 흐름을 추적하고 시장과 포지션을 모델링했으며, 문서와 시각 자료도 만들었다.
- 회사는 생산성과 위험을 검토했다고 밝혔으며, 기사는 코드 검토, 정보 차단, 비용, 대체 업무 흐름의 부재를 주요 쟁점으로 짚는다.

---

## 📝 상세 정리

### 1. 골드만삭스, 은행원과 트레이더의 클로드 코드 사용 제한

1. 10월 지침으로 코딩 에이전트 사용 대상이 좁아졌다.
   - 블룸버그는 골드만삭스가 앤스로픽의 클로드 코드와 마이크로소프트의 깃허브 사용을 엔지니어로 제한했다고 보도했다.
   - 이 정책은 생산성과 위험에 관한 검토 뒤에 나왔다.
   - 트레이딩, 정량 연구, 소프트웨어 엔지니어링을 아우르는 전략 담당자(strats)는 계속 이용할 수 있는 것으로 알려졌다.
   - 일부 트레이더는 일상 업무에 쓰던 도구를 사용하지 못하게 되어 불만을 나타냈다.
2. 이전에는 비엔지니어 직원의 시제품 제작을 장려했다.
   - 7월에 최고정보책임자(CIO) 마르코 아르젠티(Marco Argenti)는 비기술 직군의 ‘바이브 코딩(vibe coding)’을 긍정적으로 평가했고, 엔지니어들이 결과물을 개선할 수 있다고 말했다.
   - 트레이더와 은행원은 에이전트로 고객 거래 흐름을 추적하고 시장 움직임과 포지션을 모델링했다.
   - 문서와 그래픽 자료를 만드는 데도 이 도구들을 활용했다.
   - 문제에 가까이 있는 직원이 엔지니어의 작업 시간을 기다리지 않고 첫 버전을 만들 수 있었다.
   - 기사에서 인용한 아르젠티의 발언에 따르면 골드만삭스에는 약 4만 7천 명의 직원 중 엔지니어가 약 1만 2천 명 있다.
3. 이번 제한은 앞서 홍콩에서 내린 결정과 성격이 다르다.
   - 골드만삭스는 4월 홍콩 은행원의 사내 인공지능 플랫폼에서 클로드를 제외했다. 계약 해석과 서비스 제공 여부가 이유로 거론됐다.
   - 당시 해당 직원들은 챗GPT(ChatGPT)와 제미나이(Gemini)를 계속 사용할 수 있었던 것으로 보도됐다.
   - 새 제한은 지역이 아니라 직무를 기준으로 하며, 코드를 작성하고 실행할 수 있는 외부 업체의 에이전트에 적용된다.
   - 여러 회사의 모델을 쓰는 골드만삭스 자체 인공지능 도우미는 회사 전반에서 계속 제공된다.
4. 코드 실행에는 통제와 책임 문제가 따른다.
   - 클로드 코드는 파일을 읽고 프로그램을 작성해 실행할 수 있으며, 대체로 사용자의 권한을 그대로 이용한다.
   - 엔지니어가 만든 코드는 보통 검토와 시험, 배포 통제를 거치지만, 트레이더가 만든 스크립트는 그런 절차 없이 일상 업무에 들어갈 수 있다.
   - 은행은 거래 담당자와 거래 정보를 이용해 이익을 얻을 수 있는 트레이더를 분리하는 등 정보 차단을 유지해야 한다.
   - 에이전트로 만든 도구에는 이런 통제가 반영되지 않을 수 있고, 엔지니어도 검토 요청을 받지 않으면 도구를 살펴보기 어렵다.
   - 생성된 코드를 이해하지 못하는 사용자가 포지션 모델의 예외 상황을 놓치면 거래 손실로 이어질 수 있다.
5. 기사는 명확한 책임 소재와 유용한 도구를 이어갈 방안을 요구한다.
   - 기사에 따르면 골드만삭스와 모건스탠리(Morgan Stanley)는 앤스로픽 기업공개의 주관사이며, 앤스로픽은 11월 말 전에 나스닥(Nasdaq)에 종목 기호 ANT로 상장할 것으로 예상된다.
   - 필자들은 규제가 엄격한 업종에서 검토받지 않은 코드를 제한하는 판단은 타당하다고 보지만, 대체 수단 없이 접근 권한만 거둬들인 점은 비판한다.
   - 에이전트가 만든 도구가 실제 운영 데이터에 닿기 전에 담당 엔지니어를 지정하라고 권한다.
   - 코드가 지시문에서 생성됐더라도 기존 정보 차단, 데이터 권한, 소프트웨어 승인 규칙을 똑같이 적용해야 한다.
   - 도구를 없앨 때는 직원들이 어떤 일에 썼는지 기록해야 그 업무 수요를 이어서 해결할 수 있다.
   - 기사에서는 토큰 사용료 부담 가능성도 언급하고, 개발자에게 클로드 코드 사용을 늘리려는 바클레이스(Barclays)의 움직임과 비교한다.
