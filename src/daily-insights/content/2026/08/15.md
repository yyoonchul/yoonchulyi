## 📝 Detailed Notes

### 1. Agent Plugins are the future of Agent Skills

1. Agent Plugins addresses a distribution problem that Agent Skills alone did not solve.
   - A skill can provide on-demand instructions without loading unrelated expertise into the context window.
   - A tool-using skill, however, has two separate artifacts: `SKILL.md` instructions and an MCP server.
   - Previously, their connection often lived in client-specific README steps and configuration snippets.
2. The portable package retains the established skill layout and adds a small manifest layer.
   - An ADK-style `skills/<name>/SKILL.md` directory, including its scripts, references, and assets, already matches the expected structure.
   - The minimum migration is a root manifest with two required fields; published packages can add metadata such as version and licence.
   - Skill discovery is exactly one directory deep below `skills/`, so nested category directories can make skills undiscoverable.
3. `mcp.json` packages tools with the expertise that needs them.
   - It sits beside the manifest, declares the servers a skill needs, and requires each server to name its transport.
   - The specification defines stdio, streamable HTTP, and optional SSE transports; a command is one executable token, not a shell command.
   - `${PLUGIN_ROOT}` is for shipped assets and `${PLUGIN_DATA}` for writable state; the latter avoids state being lost on plugin update.
4. The format is designed to isolate failures and preserve a portable core.
   - If an MCP server fails to start, clients should still load the skills and report the server failure.
   - Unsupported or invalid server entries should be skipped without stopping other components; a missing `mcp.json` is not itself an error.
   - Client-specific hooks, commands, subagents, and rules can live in extension namespaces that other clients ignore.
5. The article frames the standard as useful, but not universal or fully mature.
   - Google lists Agents CLI and the Data Agent Kit as products that already ship Agent Plugins, alongside a growing compatible-client list.
   - Portable credentials are still absent: secrets must not be embedded, and authentication remains a per-client concern.
   - Agent Plugins 1.0.0 is a Working Draft; authors should test a plugin in a second client and use a plain skill or MCP configuration when packaging adds no value.

### 2. The AI Engineering Skills Map

1. Andrew Ng presents AI engineering as a broad capability rather than a narrow job title.
   - The map is intended to help developers decide what to learn and employers identify capable candidates.
   - Its synthesis draws on more than 10,000 job postings, dozens of structured interviews, surveys, and other online data.
   - Ng compares the category to cloud skills: many developers need them even if only some hold a dedicated title.
2. Building and deploying AI applications is the first pillar because AI outputs are inherently less predictable.
   - Practitioners need working knowledge of LLMs, context engineering, RAG, agentic workflows, machine learning, and deep learning.
   - The crucial operational task is to measure, steer, and govern behavior with statistical techniques.
   - Disciplined evaluation and error-analysis loops are presented as core methods for making systems more reliable.
3. Software engineering fundamentals remain essential for making informed trade-offs.
   - Real systems require decisions across cost, scalability, reliability, speed, security, and privacy.
   - Fundamentals improve choices about stacks, architecture, data stores, and testing.
   - They also let developers give coding agents precise context instead of accepting poorly understood “vibe coded” trade-offs.
4. Using coding agents effectively is now treated as a distinct engineering skill.
   - Developers need a realistic mental model of an agent's capabilities and limits, including when to intervene and when to let it proceed.
   - Practical techniques include context management, balancing planning against execution, and supplying verifiers or evaluations to close loops.
   - Ng also highlights clear specifications, multi-agent orchestration, production-safety risks, and continuously updating workflows as tools evolve.
5. Shaping the build shifts attention from merely implementing a specification to deciding what belongs in it.
   - Better coding agents increase the value of product sense, business context, and an understanding of customer goals.
   - Engineers can take greater ownership by identifying opportunities and moving projects forward responsibly.
   - The final common requirement is continuous learning, including knowing when to test a quick MVP and when a slower, more careful build is warranted.

## 📝 상세 정리

### 1. 에이전트 플러그인(Agent Plugins)은 에이전트 스킬(Agent Skills)의 미래다

1. 에이전트 플러그인은 에이전트 스킬만으로 해결되지 않았던 배포 문제를 다룬다.
   - 스킬은 작업에 맞을 때만 관련 지침을 불러와, 무관한 전문 지식으로 컨텍스트 창을 채우지 않게 한다.
   - 하지만 도구를 쓰는 스킬은 `SKILL.md` 지침과 MCP 서버라는 두 개의 별도 산출물로 이뤄진다.
   - 이전에는 둘의 연결이 클라이언트별 README 절차와 설정 조각에 맡겨지는 경우가 많았다.
2. 이식 가능한 패키지는 익숙한 스킬 구조를 보존하면서 작은 매니페스트 계층을 더한다.
   - 스크립트, 참고 자료, 자산을 포함한 ADK 방식의 `skills/<name>/SKILL.md` 디렉터리는 이미 요구 구조와 맞는다.
   - 최소 이전에는 필수 필드 두 개를 가진 루트 매니페스트만 필요하며, 배포용 패키지에는 버전과 라이선스 같은 메타데이터를 더할 수 있다.
   - 스킬 탐색은 `skills/` 바로 아래 한 단계만 수행하므로, 카테고리 디렉터리를 중첩하면 스킬을 발견하지 못할 수 있다.
3. `mcp.json`은 필요한 전문 지식과 도구를 함께 패키징한다.
   - 이 파일은 매니페스트 옆에 놓이며, 스킬이 필요로 하는 서버를 선언하고 각 서버의 전송 방식을 명시한다.
   - 명세는 표준 입출력(stdio), 스트리밍 가능 HTTP(streamable HTTP), 선택 사항인 SSE 전송을 정의하며, 명령은 셸 명령줄이 아닌 실행 파일 토큰 하나다.
   - `${PLUGIN_ROOT}`는 함께 배포한 자산용이고 `${PLUGIN_DATA}`는 쓰기 가능한 상태용이다. 후자를 쓰면 플러그인 업데이트 때 상태가 사라지는 일을 피할 수 있다.
4. 이 형식은 실패를 격리하고 이식 가능한 핵심을 보존하도록 설계됐다.
   - MCP 서버 시작에 실패해도 클라이언트는 스킬을 계속 불러오고 서버 실패를 보고해야 한다.
   - 지원하지 않거나 잘못된 서버 항목은 다른 구성 요소를 멈추지 않고 건너뛰어야 하며, `mcp.json`이 없는 것 자체는 오류가 아니다.
   - 클라이언트 전용 훅, 명령, 서브에이전트, 규칙은 다른 클라이언트가 무시하는 확장 이름공간에 둘 수 있다.
5. 글은 이 표준이 유용하지만 모든 상황에 맞거나 완성된 것은 아니라고 본다.
   - 구글은 에이전트 플러그인을 이미 제공하는 제품으로 Agents CLI와 데이터 에이전트 키트(Data Agent Kit)를 들고, 호환 클라이언트 목록도 늘고 있다고 설명한다.
   - 이식 가능한 자격 증명 방식은 아직 없다. 비밀 정보는 포함하면 안 되며, 인증은 클라이언트별로 처리해야 한다.
   - 에이전트 플러그인 1.0.0은 작업 초안(Working Draft)이다. 작성자는 두 번째 클라이언트에서도 플러그인을 시험하고, 패키징의 이점이 없으면 일반 스킬이나 MCP 설정을 쓰는 편이 낫다.

### 2. AI 엔지니어링 역량 지도(The AI Engineering Skills Map)

1. 앤드루 응은 AI 엔지니어링을 좁은 직무명이 아니라 폭넓은 역량으로 제시한다.
   - 이 지도는 개발자가 무엇을 배울지 정하고 고용주가 역량 있는 후보자를 찾도록 돕는 것을 목표로 한다.
   - 1만 건이 넘는 채용공고, 수십 건의 구조화된 인터뷰, 설문, 기타 온라인 데이터를 종합해 만들었다.
   - 응은 이를 클라우드 역량에 비유한다. 전담 직함을 가진 사람은 일부여도 많은 개발자에게 필요하다는 뜻이다.
2. AI 애플리케이션 구축과 배포가 첫 번째 축인 이유는 AI 출력이 본질적으로 덜 예측 가능하기 때문이다.
   - 실무자는 대규모 언어 모델(LLM), 컨텍스트 엔지니어링, 검색 증강 생성(RAG), 에이전트 워크플로, 머신러닝, 딥러닝을 이해해야 한다.
   - 핵심 운영 과제는 통계 기법으로 동작을 측정하고 조정하며 관리하는 일이다.
   - 엄격한 평가와 오류 분석 순환은 시스템을 더 신뢰할 수 있게 만드는 핵심 방법으로 제시된다.
3. 소프트웨어 엔지니어링 기초는 정보에 근거한 트레이드오프를 위해 여전히 필수다.
   - 실제 시스템에서는 비용, 확장성, 신뢰성, 속도, 보안, 프라이버시에 걸친 결정을 내려야 한다.
   - 기초 지식은 기술 스택, 아키텍처, 데이터 저장소, 테스트를 더 잘 선택하게 한다.
   - 또한 개발자가 잘 이해하지 못한 채 생성한 트레이드오프를 수용하지 않고, 코딩 에이전트에 정확한 컨텍스트를 줄 수 있게 한다.
4. 코딩 에이전트를 효과적으로 활용하는 일은 이제 별도의 엔지니어링 역량으로 다뤄진다.
   - 개발자는 에이전트의 능력과 한계, 개입할 때와 자율적으로 진행시킬 때를 현실적으로 이해해야 한다.
   - 실무 기법에는 컨텍스트 관리, 계획과 실행의 균형, 검증기나 평가를 제공해 순환을 마무리하는 방법이 포함된다.
   - 응은 명확한 명세, 다중 에이전트 조율, 프로덕션 안전 위험, 도구 발전에 맞춰 워크플로를 계속 갱신하는 일도 강조한다.
5. 빌드 방향 설정은 명세를 단순 구현하는 데서 명세에 무엇을 넣을지 정하는 일로 초점을 옮긴다.
   - 더 나은 코딩 에이전트일수록 제품 감각, 비즈니스 맥락, 고객 목표 이해의 가치가 커진다.
   - 엔지니어는 기회를 찾아 책임감 있게 프로젝트를 추진하며 더 큰 주인의식을 가질 수 있다.
   - 공통된 마지막 요건은 지속적인 학습이며, 빠른 최소 기능 제품(MVP)을 시험할 때와 더 느리지만 신중하게 구축할 때를 구분하는 일도 여기에 포함된다.
