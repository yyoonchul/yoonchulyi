## 📝 Detailed Notes

### 1. AX: an execution platform for agentic tasks

1. AX treats agents as a workload distinct from services and batch jobs.
   - The site describes agents as stateful, bursty, and potentially long-running actors rather than stateless request handlers.
   - Such jobs may wait for model APIs, tools, or human feedback while retaining task state.
   - It argues that idle sandboxes and uncontrolled tool or model loops create both cost and operational risks.
2. The control plane exposes four declarative primitives.
   - A Task represents isolated execution with CPU and memory limits and can be created, suspended, or discarded.
   - A Workspace specifies repositories, MCP servers, skills, or a natural-language setup goal for a task environment.
   - Gateway defines host-and-port network policy and can inject credentials; Model centralizes model settings and secrets.
3. The command-line example shows the intended operating model.
   - A `task.yaml` declares a Git workspace and a task whose goal is to build Go from source.
   - `ax apply`, `ax watch`, `ax ssh`, `ax suspend`, and `ax resume` cover provisioning, observation, debugging, and lifecycle control.
   - The suspended task retains its workspace state, illustrated by a file that remains after resumption.
4. AX makes scale and research use cases central to its pitch.
   - It runs on Agent Substrate, which AX describes as a runtime for dense, stateful actor lifecycles.
   - The site claims sub-second resumption and multiplexing of many waiting tasks on shared worker resources.
   - Proposed uses include coding agents, persistent agent servers, notebooks, browser tests, reinforcement-learning trajectory collection, and evaluations.

### 2. ChatGPT now knows what you do on other websites via ad collector

1. The report describes a claimed link between a ChatGPT identity and third-party ad events.
   - It says `chatgpt.com` obtains a short-lived signed token containing an account subject and an `obi` identifier.
   - According to the author, posting that token to `bzr.openai.com` sets `__obi` for `.openai.com` with `SameSite=None`, `Secure`, and a one-year lifetime.
   - That cookie configuration permits the browser to attach it to qualifying cross-site requests to OpenAI hosts.
2. Loading an advertiser's OpenAI SDK is presented as a key disclosure path.
   - The author reports seeing `__obi` on the SDK script request and on event requests from advertiser pages.
   - The report argues that an SDK path that omits credentials does not prevent the script-load request itself from carrying the cookie.
   - A pixel-configuration request was presented as a control that did not carry a cookie header.
3. The article alleges broad data collection in the SDK event payloads.
   - It says the SDK distinguishes advertiser-provided values from form fields, rendered HTML text, and tag-manager data.
   - Email addresses, phone numbers, and names are said to be SHA-256 hashed before transmission, while country, region, city, and postal code can be sent in clear text.
   - URLs reportedly omit query strings but preserve origin and path, which can still reveal sensitive browsing contexts.
4. The observations have important limits and are not an independent audit.
   - The author reports 936 advertiser pixels across 1,029 hostnames and accepted events from several commercial sites, but did not observe server-side account resolution.
   - The report says the mechanism was observed on Chrome for Android; Safari and iOS browsers should block third-party cookies under WebKit's policy, while desktop Chrome was untested.
   - OpenAI Support acknowledged the inquiry, according to the article, but the report says it did not answer why the cookie was classified as analytics or how analytics and marketing consent interact.

### 3. GPT-6 Astra: 3D, Embodied AI, and Beyond

1. Zhu distinguishes disclosed information from reporting and rumor about GPT-6 Astra.
   - The article says OpenAI has stated that Astra used a training run of more than 100,000 GPUs at Stargate, large-scale reinforcement learning, and targeted training for professional computer-use environments.
   - It labels reports of large Mac purchases and a looped-transformer architecture as unconfirmed, and Blender training plus robot or first-person data as rumor.
   - Zhu's inference is that observed gains may primarily reflect training data and the training recipe rather than a proven architectural change.
2. The article interprets Astra's 3D work as inverse graphics in an agent loop.
   - Rendering maps a scene configuration to an image; inverse graphics instead seeks a scene that reproduces an observed image or video.
   - In the proposed loop, the model writes Blender code, renders, inspects the result, identifies an error, changes the code, and repeats.
   - Zhu compares a 3D engine to the compiler and sandbox used by coding agents, while noting current weakness on organic forms such as people or animals.
3. Embodied AI is framed as increasingly capable orchestration plus policy learning.
   - A foundation model can plan, call manipulation or navigation tools, inspect results, and retry when calls fail.
   - The article says direct calls to lower-level controls, such as camera adjustment, navigation, or end-effector positions, could lower the abstraction boundary as models improve.
   - Slow large-model actions can produce demonstrations for smaller high-frequency policies running on devices, or aid real-to-sim-to-real training.
4. The proposed bottlenecks divide between model capability and the surrounding physical system.
   - Inverse physics needs both a sufficiently faithful simulator and reasoning about physical change over time; some parameters require real-world interaction to identify.
   - Embodied agents need richer sensing, particularly touch, plus action spaces and hardware capable of high-degree-of-freedom control.
   - Zhu argues that the common core is a perception-action loop with pretraining, supervised fine-tuning, and reinforcement learning, but that better models alone cannot solve simulator, sensor, or hardware limits.

## 📝 상세 정리

### 1. AX: 에이전트 작업 실행 플랫폼

1. AX는 에이전트를 서비스나 배치 작업과 다른 유형의 작업량으로 본다.
   - 사이트는 에이전트를 상태를 유지하고, 간헐적으로 부하가 커지며, 오래 실행될 수 있는 행위자로 설명한다.
   - 이러한 작업은 상태를 보존한 채 모델 API, 도구, 사람의 피드백을 기다릴 수 있다.
   - 유휴 샌드박스와 통제되지 않는 도구·모델 반복 실행은 비용과 운영 위험을 함께 만든다고 본다.
2. 제어 평면은 네 가지 선언형 기본 요소를 제공한다.
   - 작업(Task)은 CPU와 메모리 제한을 둔 격리 실행 단위이며, 생성·일시 중지·폐기가 가능하다.
   - 작업공간(Workspace)은 저장소, MCP 서버, 스킬 또는 자연어 환경 구성 목표를 지정한다.
   - 게이트웨이(Gateway)는 호스트와 포트 기반 네트워크 정책 및 자격 증명 주입을 담당하고, 모델(Model)은 모델 설정과 비밀 값을 중앙 관리한다.
3. 명령줄 예시는 의도한 운영 방식을 보여 준다.
   - `task.yaml`은 Git 작업공간과 Go를 소스에서 빌드하는 목표를 가진 작업을 선언한다.
   - `ax apply`, `ax watch`, `ax ssh`, `ax suspend`, `ax resume` 명령은 프로비저닝, 관찰, 디버깅, 생명주기 제어를 맡는다.
   - 예시에서는 작업을 재개한 뒤에도 작업공간 상태가 보존되어, 이전에 만든 파일이 남아 있음을 보여 준다.
4. AX는 대규모 실행과 연구 활용 사례를 핵심으로 내세운다.
   - AX는 고밀도 상태 유지형 행위자 생명주기를 위한 런타임인 에이전트 서브스트레이트(Agent Substrate) 위에서 실행된다고 설명한다.
   - 사이트는 1초 미만 재개와 여러 대기 작업의 워커 자원 공동 사용을 주장한다.
   - 코딩 에이전트, 지속형 에이전트 서버, 노트북, 브라우저 테스트, 강화학습 궤적 수집, 평가 작업을 활용 사례로 제시한다.

### 2. ChatGPT now knows what you do on other websites via ad collector

1. 보고서는 ChatGPT 신원과 제3자 광고 이벤트가 연결된다고 주장한다.
   - `chatgpt.com`이 계정 주체와 `obi` 식별자를 담은 짧은 유효기간의 서명 토큰을 얻는다고 작성자는 설명한다.
   - 작성자에 따르면 이 토큰을 `bzr.openai.com`에 게시하면 `SameSite=None`, `Secure`, 1년 수명을 가진 `.openai.com`용 `__obi` 쿠키가 설정된다.
   - 이 쿠키 설정은 브라우저가 조건에 맞는 오픈AI 호스트로의 교차 사이트 요청에 쿠키를 붙일 수 있게 한다.
2. 광고주가 오픈AI SDK를 불러오는 과정이 핵심 노출 경로로 제시된다.
   - 작성자는 광고주 페이지에서 SDK 스크립트 요청과 이벤트 요청에 `__obi`가 포함된 것을 봤다고 보고한다.
   - 보고서는 자격 증명을 생략하는 SDK 경로가 있어도, 스크립트를 불러오는 요청 자체에 쿠키가 실릴 수 있다고 주장한다.
   - 픽셀 설정 요청은 쿠키 헤더가 없었던 대조 사례로 제시됐다.
3. 글은 SDK 이벤트 페이로드가 폭넓은 데이터를 수집한다고 주장한다.
   - SDK는 광고주가 제공한 값, 양식 필드, 렌더링된 HTML 텍스트, 태그 관리자 데이터를 구분한다고 설명한다.
   - 이메일 주소, 전화번호, 이름은 전송 전 SHA-256으로 해시되고, 국가·지역·도시·우편번호는 평문으로 전송될 수 있다고 보고한다.
   - URL은 쿼리 문자열을 빼지만 출처와 경로는 남겨, 민감한 탐색 맥락을 드러낼 수 있다고 한다.
4. 이 관찰에는 중요한 한계가 있으며 독립 감사 결과가 아니다.
   - 작성자는 1,029개 호스트에서 광고주 픽셀 936개를 관찰했고 여러 상업 사이트의 수락된 이벤트를 봤다고 하나, 서버 측 계정 연결은 직접 보지 못했다.
   - 이 방식은 안드로이드용 크롬(Chrome for Android)에서 관찰됐다고 하며, Safari와 iOS 브라우저는 웹킷(WebKit) 정책에 따라 제3자 쿠키를 차단해야 하고 데스크톱 크롬은 시험하지 않았다고 한다.
   - 보고서는 오픈AI 지원팀이 문의를 접수했지만, 쿠키를 분석용으로 분류한 이유와 분석·마케팅 동의의 상호작용에는 답하지 않았다고 전한다.

### 3. GPT-6 Astra: 3D, Embodied AI, and Beyond

1. 주는 GPT-6 Astra에 관한 공개 정보, 보도, 소문을 구분한다.
   - 글은 오픈AI가 Stargate에서 10만 개가 넘는 GPU를 사용한 훈련, 대규모 강화학습, 전문 컴퓨터 사용 환경을 겨냥한 훈련을 밝혔다고 전한다.
   - 대량의 Mac 구매와 순환형 트랜스포머(looped transformer) 구조는 미확인 보도로, Blender 훈련과 로봇 또는 1인칭 데이터는 소문으로 표시한다.
   - 주는 관찰된 성능 향상이 입증된 아키텍처 변화보다 훈련 데이터와 훈련 방식에서 주로 나왔을 수 있다고 추론한다.
2. 글은 Astra의 3D 작업을 에이전트 순환 안의 역그래픽스로 해석한다.
   - 렌더링은 장면 구성을 이미지로 바꾸고, 역그래픽스는 관찰한 이미지나 영상을 재현할 장면을 찾는다.
   - 제안된 순환에서 모델은 Blender 코드를 작성하고, 렌더링하고, 결과를 검사해 오류를 찾아 수정한 뒤 반복한다.
   - 주는 3D 엔진을 코딩 에이전트의 컴파일러와 샌드박스에 비유하면서, 사람이나 동물 같은 유기적 형상에는 아직 약점이 있다고 지적한다.
3. 체화 AI는 점점 더 강해지는 조율과 정책 학습의 문제로 그려진다.
   - 기반 모델은 작업을 계획하고, 조작·내비게이션 도구를 호출하며, 결과를 검사하고, 호출이 실패하면 다시 시도할 수 있다.
   - 카메라 조정, 내비게이션, 말단 장치 위치 같은 저수준 제어를 직접 호출하면 모델 발전에 따라 추상화 경계를 낮출 수 있다고 본다.
   - 느린 대형 모델의 행동은 기기에서 실행되는 고주파 소형 정책을 위한 시연 데이터를 만들거나, 현실-시뮬레이션-현실 훈련을 도울 수 있다.
4. 제시된 병목은 모델 역량과 주변 물리 시스템의 한계로 나뉜다.
   - 역물리(inverse physics)에는 충분히 충실한 시뮬레이터와 시간에 따른 물리 변화를 추론하는 능력이 모두 필요하며, 일부 매개변수는 현실 상호작용이 있어야 식별할 수 있다.
   - 체화 에이전트에는 더 풍부한 감지, 특히 촉각, 그리고 높은 자유도 제어가 가능한 행동 공간과 하드웨어가 필요하다.
   - 주는 사전 훈련, 지도 미세 조정(SFT), 강화학습(RL)을 갖춘 지각-행동 순환이 공통 핵심이라고 보지만, 더 나은 모델만으로 시뮬레이터·센서·하드웨어의 한계를 해결할 수는 없다고 주장한다.
