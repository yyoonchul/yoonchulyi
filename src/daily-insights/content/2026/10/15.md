## 📝 Detailed Notes

### 1. How Anthropic’s Dynamic Workflows Coordinate Claude Agents

1. Anthropic frames flows as a flexible way to organize multi-agent work.
   - CJ Avilla and Harrison Stall presented the feature at AI Engineer New York.
   - They connected the idea to operating-system projects such as Unix and Linux.
   - Their analogy emphasizes organization and trusted layers as projects grow.
   - The goal is to let agents handle larger workloads without making developers coordinate every contribution.
2. Claude chooses the topology and writes the orchestration program.
   - A lead agent first plans how to approach a task.
   - Claude then produces a program that launches agents, gathers results, and controls information flow.
   - Earlier Managed Agents setups required developers to configure a coordinator and sub-agent roster.
   - Flows can span phases and break work into discrete, verifiable units.
3. Developers retain configuration, oversight, and cost controls.
   - Optional preconfigured specialist agents can still be passed in.
   - Claude Console graphing exposes transitions and the payloads passed to sub-agents.
   - Agents share a filesystem for exchanging information, but the API does not provide direct sub-agent messaging.
   - Developers set a session budget; the running model does not know the budget itself.
4. The added compute is meant for difficult tasks, with limits to manage.
   - In a stock-watchlist example, one phase scanned tickers in isolated contexts and a later phase reviewed findings.
   - Anthropic recommends evaluation and low defaults to avoid spawning too many agents; larger parallel runs need explicit encouragement.
   - Flows cost substantially more than a single-agent approach, though presenters said they find more details.
   - Self-improvement is not built in; the presenters suggested cost review, “dreaming” memory updates, and hill-climbing as possible aids.
   - Anthropic sees test-time compute through flows as a path toward broader access to difficult research problems.

### 2. Frontier Models for Every Robot: Announcing our API beta

1. Pi API beta packages model adaptation and inference as a managed service.
   - Physical Intelligence announced access to its latest models for training and inference.
   - Developers upload data and launch fine-tuning using company-managed compute and infrastructure.
   - Fine-tuned models are then available through a hosted gateway for robot inference.
   - The company says its latest model improves fine-tuning data efficiency and capability for partners.
2. The service aims to make general-purpose robot models easier to adapt.
   - Models such as π₀ and π₀.₅ provide prior physical knowledge and capabilities.
   - This foundation can reduce data and effort needed to adapt to new tasks, environments, or robots.
   - Building custom machine-learning infrastructure and data pipelines has otherwise been a significant hurdle.
   - Pi says it can update underlying models rapidly and plans to expose newer, more capable versions.
3. Partners tested a repeated data-to-deployment improvement loop.
   - The pattern is to collect demonstrations, train a model, test it on hardware, and use failures to decide what data comes next.
   - Physical Intelligence built the API to let developers run this cycle independently.
   - An early example showed Almond’s Axol dual-arm robot deburring spacers used in its own assembly.
   - Almond said it reached the demonstrated model after four days of iteration with the API.
4. Early use spans real settings, while deployment constraints remain.
   - Examples include Actor’s autonomous wheel loader operating commercially without an onboard operator.
   - Other partner tasks include garment handling, food-related work, and manufacturing parts placement.
   - Deployments across the United States, Japan, and Switzerland mostly used cloud-hosted inference.
   - Network connectivity was one limitation observed in some settings.
   - Pi presents broader access as a way to grow the robotics ecosystem and learn from more real-world applications; the beta remains early and open to developer feedback.

### 앤트로픽의 동적 워크플로가 클로드 에이전트를 조율하는 방식
**출처:** Latent.Space · **카테고리:** 인공지능 · **링크:** [원문](https://www.latent.space/p/claude-dynamic-workflows)

- 개발자는 세션 예산을 설정하고 클로드 콘솔에서 에이전트 간 전달을 살펴볼 수 있다. 에이전트는 파일 시스템을 공유하지만 API를 통해 서로에게 직접 메시지를 보낼 수는 없다.
- 단일 에이전트보다 비용이 많이 들지만, 병렬 작업으로 더 폭넓은 결과를 얻을 수 있는 큰 과제를 겨냥한다.

### 모든 로봇을 위한 최첨단 모델: API 베타 발표
**출처:** Physical Intelligence · **카테고리:** 로봇공학 · **링크:** [원문](https://www.pi.website/blog/api-beta)
- Physical Intelligence가 로봇 데이터를 올리고 관리형 기반 시설에서 π 모델을 미세 조정한 뒤, 호스팅 추론으로 실행할 수 있는 API 베타를 공개했다.
- 초기 협력사들은 중장비, 의류 취급, 음식 준비, 제조 등 여러 작업에 이 절차를 적용했다.
- 시연 데이터 수집, 학습, 로봇 시험, 실패를 바탕으로 한 추가 데이터 수집이 반복 절차다. 초기 배치에서는 네트워크 연결의 한계도 드러났다.

## 📝 상세 정리

### 1. 앤트로픽의 동적 워크플로가 클로드 에이전트를 조율하는 방식

1. 앤트로픽은 동적 워크플로를 여러 에이전트 작업을 유연하게 조직하는 방식으로 소개했다.
   - CJ Avilla와 Harrison Stall이 AI Engineer New York에서 이 기능을 발표했다.
   - 발표자들은 유닉스(Unix)와 리눅스(Linux) 같은 운영체제 프로젝트의 역사에서 아이디어를 끌어왔다.
   - 이 비유는 프로젝트가 커질수록 체계와 신뢰할 수 있는 계층이 중요하다는 점을 강조한다.
   - 목표는 개발자가 모든 기여를 직접 조율하지 않아도 에이전트가 더 큰 작업을 수행하게 하는 것이다.
2. 클로드가 작업 구조를 정하고 조율 프로그램을 작성한다.
   - 먼저 총괄 에이전트가 과제를 수행할 계획을 세운다.
   - 이어 클로드가 에이전트를 실행하고 결과를 모으며 정보 흐름을 관리하는 프로그램을 만든다.
   - 이전의 관리형 에이전트(Managed Agents) 구성에서는 개발자가 조정자와 하위 에이전트 목록을 설정해야 했다.
   - 동적 워크플로는 여러 단계에 걸쳐 작업을 검증 가능한 개별 단위로 나눌 수 있다.
3. 개발자는 설정과 감독, 비용 통제 권한을 유지한다.
   - 원한다면 미리 설정한 전문 에이전트를 추가로 전달할 수 있다.
   - 클로드 콘솔(Claude Console)의 그래프 기능으로 단계 간 전환과 하위 에이전트에 전달된 내용을 살펴볼 수 있다.
   - 에이전트는 정보를 주고받기 위해 파일 시스템을 공유하지만, API에는 하위 에이전트끼리 직접 메시지를 보내는 기능이 없다.
   - 개발자가 세션 예산을 설정하며, 실행 중인 모델은 예산을 직접 알지 못한다.
4. 추가 연산량은 어려운 과제에 쓰이며, 사용량을 통제해야 한다.
   - 주식 감시 목록 사례에서는 한 단계가 종목별로 분리된 환경에서 조사하고 다음 단계가 결과를 검토했다.
   - 에이전트가 지나치게 많이 실행되지 않도록 평가와 낮은 기본값을 활용하고, 병렬 실행을 늘리려면 명시적으로 설정하라는 것이 앤트로픽의 설명이다.
   - 동적 워크플로는 단일 에이전트보다 비용이 상당히 크지만, 발표자들은 더 많은 세부 사항을 찾는 데 효과적이라고 말했다.
   - 자체 개선 기능은 기본 제공되지 않는다. 발표자들은 비용 검토, 기억 저장소를 재구성하는 ‘드리밍(dreaming)’, 점진적 최적화(hill-climbing)를 보조 수단으로 제안했다.
   - 앤트로픽은 동적 워크플로로 추론 시점 연산을 늘려 어려운 연구 과제에 더 많은 사람이 도전하게 하는 것을 목표로 삼는다.

### 2. 모든 로봇을 위한 최첨단 모델: API 베타 발표

1. 파이 API(Pi API) 베타는 모델 적응과 추론을 관리형 서비스로 묶는다.
   - Physical Intelligence가 최신 모델을 학습과 추론에 사용할 수 있도록 공개했다.
   - 개발자는 데이터를 올리고 회사가 관리하는 연산 자원과 기반 시설에서 미세 조정을 시작한다.
   - 미세 조정한 모델은 호스팅 게이트웨이를 통해 로봇 추론에 사용할 수 있다.
   - 회사는 최신 모델이 협력사에 더 적은 학습 데이터로 더 나은 미세 조정과 성능을 제공한다고 밝혔다.
2. 범용 로봇 모델을 쉽게 적용하도록 돕는 것이 서비스의 목표다.
   - π₀와 π₀.₅ 같은 모델은 물리 세계에 관한 사전 지식과 기능을 제공한다.
   - 이 기반 모델은 새로운 작업, 환경, 로봇에 적응하는 데 필요한 데이터와 노력을 줄일 수 있다.
   - 기존에는 자체 기계학습 기반 시설과 복잡한 데이터 처리 절차를 마련해야 해 진입 장벽이 높았다.
   - Physical Intelligence는 기반 모델을 빠르게 갱신할 수 있으며, 더 새롭고 성능이 높은 모델도 계속 제공할 계획이다.
3. 협력사들은 데이터부터 실제 배치까지 이어지는 개선 절차를 시험했다.
   - 시연 데이터를 모아 모델을 학습하고 하드웨어에서 시험한 뒤, 실패를 보고 다음에 모을 데이터를 정한다.
   - API는 개발자가 이 반복 절차를 직접 수행하도록 만들어졌다.
   - 초기 사례에서 Almond의 양팔 로봇 Axol은 자체 조립에 쓰이는 간격재의 거친 부분을 다듬었다.
   - Almond는 API를 이용해 나흘 동안 개선 작업을 거쳐 시연된 모델을 얻었다고 밝혔다.
4. 초기 활용 범위는 실제 현장에 걸쳐 있지만 배치 제약도 남아 있다.
   - Actor의 자율 주행 휠로더는 상업 현장에서 탑승자 없이 자재를 퍼 덤프트럭에 싣는다.
   - 다른 협력 과제에는 의류 취급, 음식 관련 작업, 제조 부품 배치가 포함된다.
   - 미국, 일본, 스위스의 배치 사례 대부분은 클라우드 호스팅 추론을 사용했다.
   - 일부 현장에서는 네트워크 연결이 한계로 확인됐다.
   - Physical Intelligence는 폭넓은 API 공개가 로봇 생태계를 키우고 실제 적용 사례를 통해 더 많이 학습하게 한다고 본다. 베타는 초기 단계이며 개발자 의견을 받아 발전시킬 예정이다.
