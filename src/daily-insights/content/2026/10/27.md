### 3. Apple’s Core Advanced On-Device Model

1. Core Advanced is designed to fit large parameter capacity into a constrained device runtime.
   - Julien Simon reports Apple describes a 20-billion-parameter model with only 1–4 billion active for a given use case.
   - Most model data stays in a 4.95 GB flash file, while 636 MiB of model pages remain loaded on the Neural Engine in his M3 Max measurements.
   - The model selects experts per prompt and periodically reloads blocks, avoiding the need to keep every expert in active memory.
   - Simon observed about 2.0 GiB held by the model and safety processes two seconds after a long request, versus roughly 15 GiB for Gemma 4 26B A4B on the same Mac.
2. The architecture combines Apple research with task-specific runtime choices.
   - The analysis connects the design to Apple research on flash-resident models, instruction-following pruning, and device-oriented expert routing.
   - Simon measured consistent 294,912-byte reads from the model file and infers that each block corresponds to an expert.
   - He infers that experts are reselected roughly every 32 generated tokens; this is an interpretation of observed read patterns, not a disclosed implementation detail.
   - Apple says active parameter counts are predetermined by use case and can vary from 1 to 4 billion.
3. Compression and chip choice prioritize memory and battery efficiency.
   - Apple previously said it compressed an on-device model to about two bits per weight; Simon’s file and memory measurements are consistent with that figure.
   - During his tests, the Neural Engine drew about 4.2 watts while processing a long prompt and 3.8 watts while generating, while the GPU remained at idle clock.
   - Across 20 grade-school math questions, the Apple model used about one-third the energy of the best open build Simon tested.
   - These are measurements from one M3 Max setup and a specific comparison set, not general device-wide guarantees.
4. Apple’s stated use cases are short, bounded language tasks.
   - Apple lists summarization, entity extraction, text understanding and refinement, classification, creative writing, tagging, and game dialogue.
   - Its developer guidance cautions against basic math, coding, and logical reasoning, while describing the earlier on-device model as unsuitable for general world knowledge chat.
   - Simon reports the API exposed an 8,192-token context window on his Mac, while Apple’s documentation still said 4,096 tokens.
   - He measured the model solving 78 of 100 grade-school problems, compared with 89–94 for three open models; on 200 knowledge questions it ranked in the middle.
5. Google’s contribution and developer trade-offs remain partly inferred.
   - Apple says the model was built in collaboration with Google and that pretraining was scaled on Google’s latest cloud TPUs.
   - Simon found Apple’s token counter matched Gemma 3 on all 429 test strings, and Google’s endpoint returned Apple’s count for the same strings.
   - He infers that Google contributed the tokenizer and possibly teacher-model outputs, while Apple developed the flash design, Neural Engine programs, and device runtime.
   - Developers cannot currently pin model versions or use adapters in OS 27, according to the article’s cited statements; this limits reproducibility and tuning.
   - Simon’s findings are external measurements and labeled assumptions, not an Apple technical report; he notes that Apple’s announced report was still missing as of October 25.

### 4. Files as Memory for Always-On Agents

1. The article proposes a layered file system as a practical baseline for persistent agent memory.
   - Sourabh Kumar describes always-on agents whose context window fills within hours, requiring durable information outside active context.
   - The four layers are core user facts, dated logs, short-lived scratch notes, and searchable files for everything else.
   - Claude Code, OpenClaw, Anthropic’s API memory tool, Manus, and Cursor are cited as products that use files or file-like access patterns.
   - The shared design keeps a small subset available up front and lets the agent search other notes when needed.
2. Files work with tools and behaviors language models already know.
   - Agents can use ordinary file reading and search commands such as grep instead of relying only on a custom retrieval API.
   - Kumar cites Letta’s LoCoMo test: a GPT-4o mini agent using file tools scored 74.0%, compared with Mem0’s reported 68.5% graph result.
   - The article cautions that the setups were not identical and Letta itself questions the value of current memory benchmarks.
   - Iterative search lets an agent refine queries as it notices names, dates, or related concepts in earlier results.
3. A four-layer structure controls what gets loaded and for how long.
   - Core memory stores concise facts that should shape every reply; it is costly because it appears in every prompt.
   - Dated logs record events in append-only daily files, while a scratchpad stores work in progress with an expiry time.
   - Topic files hold longer-lived details that load only when searched; the article’s example uses Markdown files and grep.
   - A scheduled sweep can propose durable facts from logs and remove expired scratch notes outside the active agent turn.
4. Human-readable files make memory easier to inspect and restore.
   - People can open, edit, or delete a mistaken memory directly, unlike opaque embedding vectors.
   - Dated notes expose when a fact was recorded, helping an agent surface conflicting or outdated information together.
   - Storing large tool output in a file and keeping its path allows the agent to retrieve details later instead of losing them in a lossy summary.
   - Stable core content can remain in a cached prompt prefix, while changing search results arrive later as tool outputs.
5. Files are a starting point, not a complete memory system.
   - Keyword search misses synonyms, so hybrid vector and keyword indexes may help when wording varies; files can remain the source of truth.
   - Multi-user products can map file operations onto object storage or databases rather than using a literal folder per user.
   - Concurrent agents need a write strategy, such as separate logs and a single writer for shared core memory.
   - Memory poisoning, path safety, and unbounded growth need explicit controls; the article recommends validating paths and treating external content as untrusted.
   - Kumar’s conclusion is to begin with files, add indexing when observed search failures justify it, and preserve user visibility and editability.

   - 따라서 고객 유입은 출시 때 한 번 처리하는 일이 아니라 계속 수행하는 제품 활동으로 다뤄진다.
5. 수익 추산은 명시된 가정을 바탕으로 한 예시다.
   - 다운로드의 30%가 체험을 시작하고 체험자의 30%가 연 30달러를 낸다고 가정해 다운로드당 매출을 약 2.70달러로 잡는다.
   - 월간 사용자 10만 명 기준으로 제안한 기술 구성의 매출은 27만 달러, 인공지능 처리 비용은 3,500달러로 추정한다.
   - 사용자 10만 명이 각각 인공지능을 60회 호출하는 조건에서 딥시크 비용은 사용자 1,000명당 29.43달러, 제시된 오픈AI 모델은 420달러로 비교한다.
   - 작성자는 이 비교가 2026년 10월 26일 기준 공개 가격에 따른 추정이라고 밝힌다. 실제 사용량, 가격, 전환율에 따라 결과는 달라질 수 있다.

### 2. 앤스로픽의 기업 고객 확장 전략

1. 증권신고서는 모델 플랫폼 판매에서 여러 제품을 묶은 생태계 전략으로의 확장을 설명한다.
   - 앤스로픽은 클로드를 단일 용도의 서비스형 소프트웨어가 아니라 모델, 개발자 플랫폼, 사용자가 직접 쓰는 앱의 조합으로 제시한다.
   - 연간 10만 달러 이상을 지출하는 고객의 절반 이상이 클로드 플랫폼과 클로드 코드(Claude Code)나 코워크(Cowork) 같은 자체 제품을 함께 사용한다.
   - 테크크런치가 신고서를 인용해 보도한 수치에 따르면, 이 비율은 전년도 말 약 30%에서 올랐다.
   - 앤스로픽은 각 계층의 개선이 서로를 강화해 고객에게 제공하는 가치를 키운다고 주장한다.
2. 고객 기반에는 연간 지출액이 큰 기업이 늘고 있다.
   - 신고서 기준 9월 30일에 연간 10만 달러 이상 지출한 고객은 11,900곳을 넘었다.
   - 100만 달러 이상 고객은 1,900곳을 넘었고, 1,000만 달러 이상 지출한 고객은 약 250곳이었다.
   - 앤스로픽은 기업 내 클로드 배치 확대로 사용이 늘었다고 설명하고, 3분기 말 순매출 유지율을 약 900%로 보고했다.
   - 2026년 상반기 매출은 전년 동기 12억 달러에서 163억 달러로 증가했다고 신고서에 기재됐다.
3. 제품을 교차 판매하면 제품마다 새로운 구매자를 찾지 않아도 계정 가치가 높아질 수 있다.
   - 기업은 API로 시작해 엔지니어에게 클로드 코드를 도입하고, 이어 더 넓은 직원층에 코워크를 제공할 수 있다.
   - 3분기 클로드 코드를 쓰는 클로드 엔터프라이즈 고객 중 지출 상위 5%는 코딩 도구를 쓰지 않는 일반 기업 사용자 평균보다 월 지출이 약 20배 많았다.
   - 신고서는 이 지출 격차를 기업 계정 안에서 자체 앱 사용을 확장할 수 있다는 근거로 제시한다.
   - 상위 지출 집단과 전체 사용자 평균의 비교이므로, 모든 고객에게 일반적으로 적용되는 증가 폭으로 해석하면 안 된다.
4. 서비스 조직과 협력사가 클로드를 고객 환경에 도입하도록 돕는다.
   - 앤스로픽의 응용 인공지능 팀은 스타트업과 기업이 기존 기술 환경에 클로드를 통합하도록 지원한다.
   - 블랙스톤(Blackstone) 등 사모펀드와 함께한 오드 위드 앤스로픽(Ode with Anthropic)은 현장 파견 엔지니어를 기업에 보내 맞춤형 인공지능 도구를 만든다.
   - 에이더블유에스(AWS), 구글 클라우드(Google Cloud), 마이크로소프트 애저(Microsoft Azure)는 공동 판매 방식으로 외부 유통을 맡는다.
   - 앤스로픽은 고객과 직접 계약하고 클라우드 업체에 비용을 지급해 가격을 정하고 판매 경로 충돌을 피한다고 설명한다.
5. 생태계 전략은 의존성과 고객 집중 위험도 만든다.
   - 클라우드 협력사도 앤스로픽과 경쟁하기 시작했으며, 자체 수요나 투자한 경쟁사에 연산 자원을 우선 배정할 수 있다.
   - 최대 고객 한 곳 이상이 지출을 줄이거나 이탈하고 다른 고객이 이를 보충하지 못하면 사업 실적이 악화될 수 있다고 앤스로픽은 경고한다.
   - 회사는 현재 제품과 사업 모델을 고착화하기보다 새로운 제품군을 정의하는 데 더 투자할 계획이라고 밝혔다.
   - 테크크런치 보도에 따르면 앤스로픽은 즉시 논평 요청에 답하지 않았다. 이 요약의 수치와 전략은 증권신고서와 해당 보도를 바탕으로 한다.

### 3. 애플의 기기 내 모델 코어 어드밴스드

1. 코어 어드밴스드는 큰 매개변수 용량을 제한된 기기 실행 환경에 맞추도록 설계됐다.
   - 줄리앙 시몽은 애플이 매개변수 200억 개 모델을 설명하며, 사용 사례마다 10억~40억 개만 활성화한다고 전한다.
   - 모델 데이터 대부분은 4.95기가바이트 플래시 파일에 남고, 시몽의 M3 맥스 측정에서는 636메가바이트 분량이 신경망 엔진에 상주했다.
   - 요청마다 전문가 모델을 선택하고 주기적으로 블록을 다시 불러와 모든 전문가를 활성 메모리에 둘 필요를 줄인다.
   - 시몽은 긴 요청 후 2초가 지난 시점에 모델과 안전성 처리 프로세스가 약 2기가바이트를 사용했다고 측정했다. 같은 맥에서 젬마 4 26B A4B는 약 15기가바이트였다.
2. 애플 연구와 작업별 실행 방식이 함께 설계에 반영됐다.
   - 분석은 플래시 저장 모델, 지시 따르기 가지치기, 기기용 전문가 라우팅에 관한 애플 연구와 현재 구조를 연결한다.
   - 시몽은 모델 파일에서 294,912바이트 단위의 일관된 읽기를 관찰하고 각 블록이 전문가 모델에 해당한다고 추정한다.
   - 생성된 토큰 약 32개마다 전문가를 다시 고른다고 추정하지만, 이는 관찰된 읽기 패턴을 해석한 것이지 공개된 구현 세부사항은 아니다.
   - 애플은 사용 사례별로 활성 매개변수 수를 미리 정하며 10억~40억 개 범위에서 달라질 수 있다고 설명한다.
3. 압축과 칩 선택은 메모리와 배터리 효율을 우선한다.
   - 애플은 이전에 기기 내 모델을 가중치당 약 2비트로 압축했다고 밝혔다. 시몽의 파일 및 메모리 측정도 이 수치와 부합한다.
   - 긴 입력을 처리할 때 신경망 엔진은 약 4.2와트를, 생성 중에는 약 3.8와트를 소비했고 그래픽 프로세서(GPU)는 유휴 클럭을 유지했다.
   - 초등 수준 수학 문제 20개를 푼 시험에서 애플 모델은 시몽이 시험한 최선의 오픈 모델보다 에너지를 약 3분의 1만 썼다.
   - 이 결과는 특정 M3 맥스 환경과 비교 집합에서 나온 측정이며 모든 기기에 보장되는 수치는 아니다.
4. 애플이 밝힌 용도는 짧고 범위가 분명한 언어 작업이다.
   - 애플은 요약, 개체 추출, 텍스트 이해와 다듬기, 분류, 창작 글쓰기, 태그 지정, 게임 대화를 사용 사례로 제시한다.
   - 개발자 안내는 기초 수학, 코딩, 논리 추론을 피하라고 권하며, 이전 기기 내 모델은 일반 지식 대화용이 아니라고 설명한다.
   - 시몽에 따르면 맥의 API는 8,192토큰 문맥 창을 표시했지만 애플 문서에는 여전히 4,096토큰이라고 적혀 있었다.
   - 초등 수준 문제 100개 중 애플 모델은 78개를 풀었고, 오픈 모델 세 가지는 89~94개를 풀었다. 지식 질문 200개에서는 중간 순위였다.
5. 구글의 기여와 개발자 측면의 제약은 일부가 추정에 머문다.
   - 애플은 모델이 구글과 협력해 개발됐고 구글의 최신 클라우드 텐서처리장치(TPU)로 사전 학습 규모를 키웠다고 밝혔다.
   - 시몽은 시험한 문자열 429개 모두에서 애플의 토큰 계수가 젬마 3와 일치했고, 구글 계수 서비스도 같은 문자열에 애플과 같은 결과를 냈다고 확인했다.
   - 시몽은 구글이 토큰화 방식과 교사 모델 출력을 제공했을 가능성을 추정하고, 플래시 설계, 신경망 엔진 프로그램, 기기 실행 환경은 애플이 만들었다고 본다.
   - 보도에 인용된 발언에 따르면 개발자는 현재 모델 버전을 고정하거나 OS 27에서 어댑터를 쓸 수 없어 재현성과 조정에 제약이 있다.
   - 시몽의 결과는 외부 측정과 명시된 가정이며 애플의 공식 기술 보고서가 아니다. 발표했던 보고서는 10월 25일 기준 공개되지 않았다고 적었다.

### 4. 상시 실행 에이전트의 기억 저장소로서 파일

1. 글은 지속형 에이전트 기억의 실용적인 출발점으로 파일 기반의 여러 겹 구조를 제안한다.
   - 수라브 쿠마르는 상시 실행 에이전트의 문맥 창이 몇 시간 안에 차기 때문에 활성 문맥 바깥에 오래 남는 정보를 저장해야 한다고 설명한다.
   - 네 계층은 사용자 핵심 정보, 날짜별 기록, 짧게 유지되는 임시 메모, 그 밖의 검색 가능한 파일이다.
   - 클로드 코드, 오픈클로, 앤스로픽 API 메모리 도구, 매너스, 커서는 파일 또는 파일과 유사한 접근 방식을 쓰는 사례로 소개된다.
   - 공통 구조는 일부만 처음부터 불러오고, 나머지는 필요할 때 에이전트가 검색하게 한다.
2. 파일 방식은 언어 모델이 이미 익숙한 도구와 동작을 활용한다.
   - 에이전트는 맞춤 검색 API에만 의존하지 않고 일반 파일 읽기와 그렙(grep) 같은 검색 명령을 쓸 수 있다.
   - 쿠마르는 레타(Letta)의 로코모(LoCoMo) 시험을 인용한다. 파일 도구를 쓴 GPT-4o mini 에이전트는 74.0%를 기록했고, 멤제로(Mem0)의 그래프 방식은 68.5%로 보고됐다.
   - 시험 조건이 같지 않았으며 레타도 현재 기억력 벤치마크의 의미에 의문을 제기한다고 글은 주의를 덧붙인다.
   - 반복 검색을 통해 앞선 결과에서 발견한 이름, 날짜, 관련 개념을 바탕으로 질문을 구체화할 수 있다.
3. 네 계층은 무엇을 언제 불러올지와 정보의 수명을 통제한다.
   - 핵심 기억에는 모든 답변에 반영해야 할 짧은 사실을 두며, 매 요청마다 입력되므로 비용이 크다.
   - 날짜별 기록은 매일 추가만 하는 파일에 사건을 남기고, 임시 메모는 진행 중인 작업과 만료 시각을 기록한다.
   - 주제별 파일에는 오래 유지할 세부 내용을 담고 검색할 때만 불러온다. 글의 예시는 마크다운 파일과 그렙을 사용한다.
   - 정기 작업은 기록에서 오래 유지할 사실을 제안하고, 에이전트가 작업하는 도중이 아니라 별도 과정에서 만료된 임시 메모를 지울 수 있다.
4. 사람이 읽을 수 있는 파일은 기억을 점검하고 복구하기 쉽게 한다.
   - 사람은 잘못된 기억을 직접 열어 고치거나 삭제할 수 있다. 내용을 읽기 어려운 임베딩 벡터와는 다르다.
   - 날짜가 붙은 기록은 정보가 언제 기록됐는지 드러내므로, 서로 충돌하거나 오래된 사실을 함께 보여주기 쉽다.
   - 긴 도구 출력을 파일에 저장하고 경로를 남기면, 손실이 있는 요약 대신 필요할 때 세부 내용을 다시 읽을 수 있다.
   - 안정된 핵심 내용은 캐시되는 입력 앞부분에 둘 수 있고, 변하는 검색 결과는 이후 도구 출력으로 전달할 수 있다.
5. 파일은 출발점이지 완성된 기억 체계는 아니다.
   - 키워드 검색은 유의어를 놓치므로, 표현이 달라지는 문제에는 의미 검색과 키워드 검색을 함께 쓰는 색인이 도움이 될 수 있다. 원본은 파일에 둘 수 있다.
   - 여러 사용자를 둔 제품은 사용자마다 실제 폴더를 만들지 않고도 파일 동작을 객체 저장소나 데이터베이스에 연결할 수 있다.
   - 여러 에이전트가 동시에 쓸 때는 기록을 나누고 공통 핵심 파일은 한 작성자만 수정하도록 하는 등 쓰기 규칙이 필요하다.
   - 기억 오염, 경로 안전, 끝없이 늘어나는 파일을 별도로 통제해야 한다. 글은 경로를 검증하고 외부 내용을 신뢰할 수 없는 자료로 취급하라고 권한다.
   - 쿠마르는 파일부터 시작하고 실제 검색 실패가 확인될 때 색인을 더하며, 사용자가 내용을 보고 수정할 수 있게 하라고 결론짓는다.
